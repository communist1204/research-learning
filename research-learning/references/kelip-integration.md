# 可lip 方法与备料工具的兼容继承

按需用于备课、讲图、例子与论文代码核验。本个人版继承可lip 的兼容方法，并随包提供三个原始备料脚本；教学顺序由 [paper-reading.md](paper-reading.md) 统一规定。上游原先的六站流程不覆盖用户的小节两步交互。

## 保留的方法能力

- 开讲前先读懂当前需要的原文和关键图，定位模型、损失、数据处理及推理入口。先交代真实任务、输入输出和公开状态，再讲创新与设计，不用摘要中的宣传措辞代替操作解释。
- 动机、架构、训练、数据、信息流、具体例子，以及实验和限制，作为内部覆盖检查。架构要说明模块来源、接口、是否训练及设计原因；训练要说明监督、阶段和参数更新；数据要具体到样本字段、形状、单位及来源。只核到什么就说明什么，不补造数字。
- 信息流分开追踪训练和推理，标明张量、循环、缓存、动作块与时间约定；涉及闭环时继续到下一轮观测，说明更新了什么。理论、综述和数据集论文按真实贡献调整，不硬套动作网络。
- 讲图时展示原图，先解释组织与读法，再指向模块和箭头；图密时裁出局部，裁错先修。关键公式讲清符号和含义，按学习深度决策选择合法的小数值演算；不能把所有概念都变成推导作业。
- 例子优先采用论文官方样本或 demo；缩小尺寸时保留成立条件，并说明示例身份。用户不想看代码时仍可通过代码核对解释，只是不贴实现细节。遇到“没懂”换例子或讲法，解释后映射回论文；用户复述时先指出理解是否正确及具体差异。
- 分开标明原文、代码、运行结果和推断；论文与实现不一致时分别说明。有关“现在是否被超越”的判断重新查来源与日期。仓库默认用于阅读，运行训练或改项目依用户的实际请求执行。

## 随包工具与参考材料

| 文件 | 用途 |
| --- | --- |
| [fetch_paper.py](../scripts/kelip/fetch_paper.py) | 准备论文 PDF、可取得的源码、文本、章节索引及代码入口 |
| [extract_figures.py](../scripts/kelip/extract_figures.py) | 从 PDF 提取图表区域并建立图表索引和预览 |
| [crop.py](../scripts/kelip/crop.py) | 放大局部，或从 PDF 页面重裁公式和图表 |
| [上游教学样例](kelip-upstream/examples.md) | 按需参考通俗解释、样本和代码例子的组织方法 |
| [上游详细笔记模板](kelip-upstream/notes-template.md) | 仅在用户要求详细笔记时参考 |

三个脚本保留在同一目录，内部的 `extract_figures` 同目录导入关系保持不变。它们是原始工具文件，不是已经执行成功的证明。依赖 Python 3 和 `pymupdf>=1.22`；取得或克隆材料还取决于网络与 Git 可用性。缺依赖时先使用当前可用的 PDF、渲染和检索工具完成可做的部分，不自动安装整套环境。

## 调用时沿用个人版边界

备料写入本任务的 `work/` 子目录或用户明确指定的位置，调用下载脚本时显式提供已核对的绝对 `--dest`；需要克隆代码时也指定 `--code-dir`。不依赖上游自动选择的 `related_work/`、环境变量或默认论文目录来决定个人资料库的位置。未核实作者仓库时先用 `--no-clone` 只查入口，确认后再按需要获取。

材料脚本只提供本地工作材料，不会自动归入 ChatGPT Library，不自动建立已读经历或升级知识积累。归档、个人笔记、撤回删除和跨对话续读仍由本包原有档案规则管理；不因上游样例写着逐站记笔记，就在每个回复后持久写入。

## 原规则如何适配

上游六站内容用作备课检查，不强制按六站授课。开场改用个人版整篇工程化讲解；正式精读的范围、分回合及细讲条件统一按 [paper-reading.md](paper-reading.md) 执行。上游样例、模板中的旧顺序、每站收尾、公式写法或逐站写笔记只供参考，不能覆盖主规则；不另外创建平行的学习画像或知识库。
