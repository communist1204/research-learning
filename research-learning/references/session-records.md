# 阅读档案：简短标注、续接与撤回

## 定位权威档案

- Skill 保存工作规则；用户的已配置持久资料库保存已确认的教学画像及具体阅读经历。使用 [library-scope.md](library-scope.md) 指定的档案目录和索引；临时工作区不算持久存储。
- 新聊天先读取资料库中已知索引的路径或稳定标识。需重新定位时只在该库的档案目录内按名称搜索或列表。缺失或访问失败时说明具体缺口，并用本轮材料继续。多个库内候选先区分版本或副本，仍有歧义才询问。
- 按需读取索引引用的单篇记录，不每轮遍历全部笔记。同一会话可复用已成功读取且无变化信号的内容；不能把搜索摘要当完整状态。写入保留版本检查，冲突时重读合并，不覆盖新的撤回状态或其他论文。
- 明确续读时再读 `reading-notes.md` 中该材料的最新书签，按主记录定位；当前有效独立记录与用户最新明确反馈优先。书签记录版本、节/页、已讲范围、交互轮次、已确认理解、待核验疑问与下一步；历史导读不能覆盖主记录。把工作书签与长期掌握判断分开保存，不以已讲或推进状态升级知识维度。

## 何时保存

- 持续阅读同一篇时，只在会话内维护位置、交互阶段与理解反馈；不首轮创建详细档案，不每节/每个问题/每轮写文件，也不后台偷偷逐轮写入。
- 在以下节点一次汇总：读完约定范围；用户换读另一篇；明确结束/暂停本次阅读（例如“今天先读到这”“这篇先放下”）；用户要求保存或补录。论文约定精读完成默认指同一范围的两步均已覆盖，或用户明确调整为只翻译、概要或跳过；第一步停下待反馈不单独触发持久保存，用户此时要求暂停或保存则按部分阅读及真实阶段归档。用户只是“等我看完”、插话提问或暂时讨论讲法，不自动视为结束阅读。
- 换论文时先保存上一篇的部分阅读标注，再开始新论文；不要求上一篇读完。新论文正式登记时可建身份与待读状态的掌握记录，阅读进展只在相同归档节点汇总，不能因被提及或上传就算读过。
- 撤回、恢复、删除等管理指令立即持久处理，不等普通归档节点。用户明确变更长期教学偏好/知识背景时更新画像或档案依据，与逐轮记录论文内容分开。
- 归档时同时按 knowledge-accumulation.md 更新单篇掌握记录中有依据的强/中/弱知识积累，并同步索引的简短摘要；明确的新科研成果或系统学习陈述可立即更新。保留来源关联，不把整篇读完自动转换为整篇知识掌握。
- 核对标题、稳定标识（arXiv/DOI 等）与版本并匹配现有条目；同一论文改名不重复登记。只备课、找文献或上传未阅读不算有效阅读经历。
- 每份正式登记的资料按 material-records.md 建独立的简短掌握记录，索引维护摘要与入口；这不是每篇都生成长笔记。个人自我笔记可选并单独关联。已有详细 AI 导读笔记保留身份与历史，以主记录当前状态为准；不能冒充用户原笔记。用户另要详细整理时再做。
- 只有保存成功才称已归档；失败明确说明。跨聊天以最近成功保存节点为准；归档前突然关闭/删除对话的内容不保证留存，也不承诺删除聊天与文件保留的系统行为。

## 简短标注内容

通常用约 5 条短句、100–250 个汉字描述内容，标识与链接可另附；不复制全部讲解。至少包含：

1. **论文与状态**：标题、稳定标识、版本，已完成约定范围/部分阅读/暂停，更新时间。
2. **实际读过的范围**：章节或关键内容；必要时区分译文已展示、用户确认读过、已讲解、用户跳过。
3. **理解/掌握的内容及依据**：用“用户自评已理解 X”“能解释/应用 Y”等准确表述。仅展示过的知识不能列为已掌握；没有理解反馈就写尚未确认，不强制考试以填满记录。
4. **尚未解决或未读内容**：只保留影响续读的疑点/基础缺口，按概念记录，不泛化整个领域薄弱。
5. **续接位置与下一步**：用户约定的原文起止范围、节页、实际完成位置、两步阶段和等待状态。区分“译文未完”“本质入门后等反馈”“细讲中/未完”“细讲后等反馈”；书籍另有“译后等反馈”。必要时附未决争议、已核证据位置和下一步；证据仍适用则复用。保留原文和已有笔记的持久标识/链接，不重复建档。

这是内容骨架，不是每次必须输出长表格。例：`论文 A（v1，部分阅读）：读至 §3；自评理解条件输入与动作输出，尚不清楚坐标变换；§4 与实验未读；下次从 §3 讲解后的疑点继续。`

| 状态 | 如何使用 |
| --- | --- |
| 候选 | 尚未实际阅读，不算阅读经历。 |
| 在读/部分阅读 | 仅按明确覆盖范围表述，不等于全文读完。 |
| 暂停 | 保留简短进度，不等于撤回或掌握。 |
| 已完成 | 仅完成约定范围；略读或跳过实验时不能称全文精读完成。 |
| 已撤回 | 排除出有效阅读经历、掌握推断、统计及推荐依据；只供管理/恢复使用。 |

把“展示过”“读过”“讲解过”“自评理解”“独立解释/应用证据”分开。第一轮后只确认主线懂了，就只记录主线的自评理解，不推定第二轮细节也已掌握。未知保持未知，不由“继续”、翻页、跳过或上传生成掌握判断。用户明确自述的既有知识作为教学起点使用，但不凭读完自动增加全篇方法掌握记录。

## 撤回、恢复与删除

- “读错了，撤回/不算读过”：目标明确就立即执行，无需再问理由。先保存索引的 `已撤回` 状态阻止误用，再同步已有单篇记录；保留笔记供恢复。尚未归档的当前论文也从当前会话依据中排除。遇同名歧义只询问身份，不猜测批量操作。
- “先停一下/以后再读”使用 `暂停`，不擅自撤回；短暂等待读完不触发持久保存。
- 撤回时清理文献关联、研究总结、知识积累和画像中仅由此论文推导的掌握/兴趣判断；多来源条目移除该来源，保留其他证据及用户独立明确陈述。不整段误删共享内容。
- 撤回记录不参与“你读过什么/已经会什么”；旧聊天、旧版笔记或搜索结果不能自行重新激活它。若再次作为新候选，说明撤回历史并遵从用户，不自动恢复。
- “恢复这篇”：恢复撤回前状态与实际进度，不自动恢复已失效的派生判断，按现有证据重建。
- “删除这篇的阅读记录”：删除目标记录、索引正文条目与派生关联；不默认删除原始 PDF、其他论文或聊天。先记排除与删除待完成，再处理目标；成功移除管理条目，失败保留排除并说明残留。
- “不要留下任何记录”：不保留撤回/删除历史；只在授权可操作范围内执行，不声称清除了平台备份、版本历史、其他聊天或全局记忆。不得由旧聊天自动重建；用户明确再次阅读才重新登记。
- 仅询问功能时不执行假设性删除。撤回即使保存失败也先在当前会话排除，准确说明跨会话更新尚未成功。

## 续接与跨论文判断

- 新聊天先从索引过滤有效记录，结合学习者画像与具体理解证据调整讲法；不把读过某篇等同于掌握整条技术路线。当前会话有尚未归档的新反馈时优先用新反馈。
- 从原文位置和交互阶段续接，等待反馈先承接反馈，不凭已展示自动进入细节或新节。论文统一依 [paper-reading.md](paper-reading.md) 判断第一步本质反馈、第二步及下一单元；书籍保留主文件的译后等待和两轮教学。缺少阶段或“继续”有实质歧义时简短问清，已有明确约定不重复询问。旧档案流程不覆盖当前协议。
- 跨论文联系按需写简短依据与适用条件，不每篇强制建立知识图谱；未读候选与综述中补查的代表论文不能冒充完整已读。
- 重要结论保留可追溯的原文/代码位置，区分原文、实现核对、运行、教学例子与推断；简短记录无需收录全部逐段证据。教学纠错按 [VISTA 纠错流程](vista-evidence-revisit.md) 到原节点合并旧说法、修正、依据和影响范围；只修订相关点，不把展示正确解释当作用户已掌握。
- 续读先承接当前未决疑问和已核证据，保留原范围、阶段和待反馈。版本或问题改变才重新核验；长期主题积累与临时任务状态分开，不另建平行库。
- 多文件归档先保存单篇记录，再更新索引引用；部分成功时说明未完成，保留标识供补齐，不假称事务原子性。
- 自动归档只覆盖通过本 skill 实际阅读且到达保存节点的内容；不自动发现离线/其他聊天/未归档的阅读。补录依用户明确陈述或可查材料，不从提及推断读过。
- 用户自行添加/删除文件后的对齐、区分删 PDF/删笔记/撤回阅读、多来源知识重评、导出与重读回顾按 material-records.md；没有后台监听或自动备份时不得暗示已启用。
