# 论文小节精读协议

更新于 2026-11-07。本文件是论文精读范围、两个对话回合及阶段推进的唯一详细定义。主文件提供入口，画像和索引引用本协议。每个小节必须分开两个对话回合。先完成第一回合并结束回复，只有用户在之后明确要求细讲同一小节，才开始第二回合。旧档案、上游流程和历史原文中的交互规则与本协议冲突时，以本协议为准。

开讲前先深入读懂当前范围及必要上下文，核清关键机制，再组织讲解；不把术语拼接当成解释，无法核实的地方保留说明。本协议承接主文件的完整性、短句、连贯衔接和复习条件，不降低原有教学质量。

## 范围先听用户的

- 用户明确说“从哪里讲到哪里”时，按指定起止段、页码、公式、标题或小节范围执行。指定范围跨多个自然小节时逐小节推进。只有用户明确指定把整章或一段作为一个小节时，才按一个单元执行。保留指定的总范围与顺序。
- 用户没有指定范围时，才按原文自然小节、内容逻辑和当前理解需要判断组织，简短交代标题、页码或起止段。不把一个自然小节擅自缩成一句；长章节可沿原有小节组织。
- 所指起止位置有实质歧义时只问必要的定位问题；能从材料和上下文确定就直接执行。
- 同一约定范围同时适用于第一步与第二步，第二步继续讲这段原文，不跳到下一节。确受长度或材料限制时交代已完成范围、未完位置和当前步骤；保留用户指定的总范围，不把部分完成说成整个单元完成。完整翻译指本次约定范围，不是每轮重译整篇；确需跨回复时先完成该范围的译文，再开始本质入门。

## 第一回合 只做忠实翻译与返璞归真

1. 简要说明当前范围和“本节第一步”。在允许翻译的来源范围内忠实翻译约定原文，保留原文全部信息、论证关系、必要顺序、限定条件、引用编号、图表和公式对应、作者符号。可按主文件的首要教学原则拆分或合并段落、添加概括性小标题，或把并列项和步骤整理成列表。必要时术语首次保留英文。译文不混入教学、评价或外部补充；原文歧义或错误另列简短译注。中文原文不重复翻译。
2. 翻译后，在同一回复主动用最朴素的大白话讲本质和实际操作：这段想干什么，为什么需要，输入是什么，做了哪些操作，输出是什么，在整篇方法中起什么作用。先把操作说直观，再联系作者表达；不是翻译后就停下来等用户列问题。默认用一小段或少量短条目，把问题、操作、结果串起来；不逐条复述译文中的全部名词、精确参数、公式、实现和边界条件。主线须准确，省略会造成误解的关键前提需简短说明，其余细节留在第二步。
3. 原文已有的公式、图表、代码和例子仍按忠实翻译所需保留。第一回合的返璞归真只解释核心意思与最基本的实际操作，保留理解本质所需的前提。公式分析、推导、图表解读、代码拆解和教学例子均留到第二回合。
4. 解释完本质后可以简短提示用户可要求细讲，也可跳到下一小节。**在这里结束回复，等待用户反馈。不得把详细讲解写进同一条回复。** 两个独立对话回合指同一聊天中的不同助手回复，中间必须有用户发言。

## 等待反馈与用户主动跳过

- 用户说没懂或提出本质疑问，先留在第一步，换讲法、补最小基础或例子，再回到原文确认。不要只把术语说得更长，也不要趁回答问题自动进入整节详细讲解。
- 第一回合结束后，只有用户随后明确要求细讲当前小节，才进入第二回合。有效请求如“请详细讲这一节”或“明白了，讲细节吧”。用户无需先证明已懂或复述主线。
- 仅说“懂了”“看完了”、没有问题或沉默时，继续等待用户选择。第一回合未完时说“继续”，先完成第一回合。第一回合已结束但“继续”的含义不清时，只简短问清。用户在第一回合前说“直接细讲”或“一次都讲完”，也应先完成第一回合并停下。
- 用户明确选择“跳过详细讲解，下一节”或直接说“下一节”时，立即开始下一小节的第一回合，重新给忠实翻译与返璞归真，然后停下。只说“跳过细节”且下一小节可确定时，同样按此执行。保留实际跳过范围。上一小节的细讲请求不会授权新小节的第二回合。
- 用户明确只翻译或单独问一个问题时，按限定范围处理并保留当前精读阶段。回答局部问题不会触发或完成整节第二回合。

## 第二回合 经用户明确要求后系统细讲同一小节

1. 先按因果、操作顺序或分类层次组织连贯讲解，再逐段对照约定范围，使每项实质内容都有易懂的对应解释。覆盖概念、步骤、图表、公式、必要推导、网络或算法、代码实现、教学例子，以及假设、条件、限制、例外和论据。讲清相互关系，不能以译文已展示代替讲解。第一步已讲清的部分简短接回主线；已有疑问融入细讲，但不能只答疑而漏掉其他内容。
2. **详细讲解依然使用大白话、通俗语言和短句。**一句尽量讲一件事，先讲实际意思和操作，再引入必要术语。详细指步骤、原因与关系说完整，不是换成晦涩学术语言或堆长句。难点可分段、逐步讲，听不懂就换讲法。
3. 公式说明关键符号、量的含义、维度、必要的单位和坐标约定，解释计算在做什么及为什么需要；依学习深度机制选择必要推导，交代前提、中间步骤和成立条件。用满足算法条件的小数值例子，不要求把所有证明补完才继续研究。
4. 讲图前实际查看原图并展示，先讲组织和读法，再讲模块、箭头与本节关系；图注不能替代看图。代码说明输入输出、张量形状、关键操作与论文对应，不仅丢仓库链接。无源码、无官方代码或材料不可读时按主文件的证据边界说明缺口，不编造实现。
5. 结合相关强、中、弱积累决定讲解起点。熟悉部分直接连接，新概念、明确缺口和必要先修用定义、直观例子与逐步分析补足，再回到原文。知识库无记录不等于没学过；不用更多未解释术语解释旧术语。是否回顾旧知识统一按主文件的依赖程度与记忆判断规则，不按强中弱层次自动复习。必要时按需查可靠原论文、代码或用真实图、视频、样本辅助，只在比纯文字更有助理解时使用，随后返回原文；不因真实材料而增加负担或偏离主线。
6. 完成本步后再自然询问是否清楚、还有哪里卡住，**结束回复等待反馈**。疑问留在本节处理；用户明确继续下一小节或跳转时再前进，下一小节重新从第一步开始。不自动一口气讲多个单元。

## 当前阶段决定怎样继续

| 当前状态或用户指令 | 执行 |
| --- | --- |
| 整篇工程化导读结束，尚未收到开始精读指令 | 等待开始或继续整体答疑，不自动翻译。 |
| 第一步未完时说“继续” | 接着完成本范围的翻译与本质，不进入第二步。 |
| 第一步结束，用户说本质没懂或提出本质问题 | 留在第一步，解释并等待理解反馈。 |
| 第一回合结束，用户明确要求细讲当前小节 | 在独立的后续回复详细讲解该小节。 |
| 第一回合结束，用户只说“懂了”或“看完了” | 保留当前小节，等待用户明确选择。 |
| 第一步结束只说“继续”，意图不清 | 只问继续解释本质还是进入详细讲解；已有明确约定时不重复问。 |
| 第二步未完时说“继续” | 接着本节详细讲解，保留未完位置。 |
| 第二步已完并交互后说“继续”或“下一节” | 下一单元第一步；这不是掌握证明。 |
| 任意阶段明确说“下一节”“这节不用讲”“跳过细节”或指定跳转 | 直接跳转或跳过。下一小节必须重新从忠实翻译与返璞归真开始，随后停下。 |
| “等一下”“没看完” | 暂停等待，不开新内容。 |
| 用户讨论流程、纠正规则或插话 | 先处理当前问题并保留返回位置，不擅自恢复论文或翻页。 |

用户仍决定指定范围、只讲某点、只翻译、跳过或暂停。每个小节的两回合边界继续适用。不要把第一步本质已懂记录成第二步的公式、推导和实现也已掌握；两步完成不自动等于全文读完或强积累。

## 内容完整与记录边界

- 实验、相关工作和结论等不承载核心方法或理论的部分，第二步的讲解可以概要，交代实验设计、结果、消融、结论及局限；含关键新方法、推导或训练细节的部分仍按需要讲透。第一步仍忠实翻译约定范围，只有用户明确同意略读、概要或跳过时才调整；不能借“实验可概要”省略约定译文。不凭章节名称遗漏核心内容，不把概要说成完整翻译，据实记录实际覆盖和跳过范围。
- 正式精读前仍先做整篇工程化解构并等待开始；已明确进入精读、直接提问或续读时承接当前阶段，不重启导读。
- 仅在会话内维护当前原文范围、第一步或第二步、实际完成位置及等待哪类反馈。持久归档仍按 session-records.md 的原节点，不因增加一个交互节点就逐轮写入。
- 归档区分译文已展示、本质已讲及理解反馈、细节已讲及理解范围、未解决问题、跳过内容和下次位置。不以“继续”、无提问、翻页、成功运行代码或愿意听讲推定掌握，也不要求证明掌握才能翻页。
