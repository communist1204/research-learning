# VISTA 启发的证据回溯与状态恢复

本 Skill 借鉴 VISTA 的原始证据核验、历史回看、信息分层与状态恢复机制。精读按指定范围、两回合和原有归档节点执行。个人资料限于 [指定科研资料库](library-scope.md) 与本轮明确提供的材料。可用公开论文与源码核验结论，个人阅读状态仍依据独立有效记录。

## 四类信息分层

| 层级 | 内容 | 使用边界 |
| --- | --- | --- |
| A 原始证据 | 匹配版本的原论文、作者图表、公式、官方源码、真实样本及实验结果 | 保留稳定引用、页节图式或源码路径；AI总结不能替代原证据 |
| B 个人长期知识 | 独立掌握记录、相关先修强中弱及实际理解边界 | 只依明确反馈、独立理解或实际应用证据提升；助手讲解不自动成为掌握证据 |
| C 当前任务状态 | 版本、节页、指定范围、论文两步阶段或书籍译后等待及入门/细讲阶段、已讲范围、关键疑问、未核判断及下一步 | 作为可更新续读书签，不覆盖长期知识 |
| D 本轮推理与教学 | 助手解释、教学构造、尚未证实的推断 | 不伪装为作者原话、真实配对样本或实测实验；未核实须标明 |

## 何时直接答 何时回溯

问题简单且现有可靠材料已经足够时，直接回答。不仅因为启动了本 Skill 就重新下载论文、读完整仓库、生成四维评级表或重启整篇导读。

遇到以下情况才按需启动证据回溯：用户指出解释与原文或图不符；公式、图表与代码互相矛盾；关键结论证据不足；版本差异会改变回答；当前结果无法正确解释。坐标方向、投影关系、变换顺序、时间步、张量维度、正负号、下标、条件分布、创新归属或实验数值存在混淆时，也按具体疑点核对；既有知识记录与新证据冲突时同样处理。先检查当前原文和已有有效证据，再获取最少的补充材料。学习深度仍由当前研究需要决定，不因启动回溯就自动展开完整数学课程。

## 证据回溯闭环

1. **定位一个具体问题。** 说清要核对的主张、符号、图中箭头、实现步骤或结果是什么，保留当前论文版本、用户指定范围与第一步或第二步阶段。不把局部疑问扩大成整篇重读。
2. **选取必要的原始材料。** 优先查看相关原文上下文、图、公式、附录或作者官方实现。涉及图像、公式排版或空间关系，必须实际打开相应原始 PDF 页图，必要时放大或裁图。图注、OCR、低清预览、旧截图或模型记忆不能替代原图；非必要不反复全本 OCR。图要实际查看，图注不能替代看图；公式检查定义、前提、索引、单位与必要坐标约定；代码检查相关函数与配置并保留版本位置。依问题选择，不强制每次把所有材料都查一遍。
3. **对照并辨别差异。** 检查是否同一论文版本、同一任务设定；区分原文、代码、运行证据、教学示例、用户观点与 agent 推断。源码不自动比论文正确；读取代码不等于实际复现。必要时用明确标注的小数值例子核对计算。
4. **给出有边界的结论。** 用通俗短句说明原说法得到支持、需要修正，还是仍未解决，并给原文页节图式或代码版本及位置。推断标明为推断。不能取得决定性材料时说明缺口、收窄结论，不反复搜索后编一个确定答案。
5. **回到原教学位置。** 将核验结果用于回答用户当前问题，再承接原范围与原阶段。第一步本质疑问处理后仍等待本质理解反馈；第二步疑问处理后接着该范围细讲。书籍按原有译后等待、入门及细讲节点承接。核验完成不授权翻页，也不代替用户确认理解。

可靠证据已足够回答、争议已定位清楚，或必要材料当前确实不可得时就停止扩查。除出现新问题、新版本或证据变化外，复用已核过的相关证据，避免每次重复深查。无证据支持的未决问题保留为未决，不以讨论次数变成结论。

**投影方向核验示例。** 有读者疑惑“把空间网格位置投影到照片上”和“把图像特征聚合到统一网格”是否矛盾时，核对匹配版本的原文、图与投影采样关系。检查是否由空间网格发起投影查询每张图的特征，再汇总到网格。查询方向与输出组织方向可以不同；以当前论文的实际证据为准。

## 四种理解落实到教学起点

方法理解、公式作用、公式推导和代码实现分别保留实际理解范围、缺口和依据，关联原有强、中、弱积累。不另造统一总分，不要求四项都达标；未涉及或未确认的维度不强行赋级，用户只说“公式中积累”时不擅自细分为推导或实现也掌握。

备课和答疑只读取本次相关维度：方法已熟就直接衔接，不重教整条流程；知道公式的作用但推导未懂，就先解释本次关键计算，是否补推导再按研究需要决定；方法懂但实现未核实，就明确实现缺口并按需要定位代码。不能因某一维较弱把其他维度一起降级。

论文第一步对本质的确认只支持对应方法范围，不自动覆盖第二步的公式、推导和实现。公式作用懂了不等于能推导，代码跑通也不等于理解证明；反向同样不能自动推定。使用用户明确自述作为教学起点，不要求考试或强制复述。

## 纠错如何进入原档案

确认先前解释有误时，明确说清原来哪点不准确、现在如何理解、核验依据在哪里以及影响哪些知识或结论。只修正受影响的点及派生关联，不把一次局部错误扩大成整篇未懂，也不悄悄覆盖原说法而不解释。

普通教学纠错先在当前会话保留一条简短的“旧说法 → 修正 → 证据位置 → 影响范围”；到原定归档节点合并进对应掌握记录与索引，不另开纠错库、不每轮写入。用户明确要求修正知识记录、撤回或删除时仍依原管理规则立即处理。若只是纠正 agent 的讲法，而用户此前未接受该错误理解，不把错误归到用户掌握状态。

正确解释已展示，不等于用户已经理解修正内容。原记录若曾以错误证据支持某点掌握，只取消或修订该点无效依据；有其他有效来源的部分保留。持久更新必须重新读取验证，未成功时说清仅在当前会话纠正了什么。

## 长期知识与临时状态分开

长期知识保存稳定的理解范围、维度、层次、来源和缺口。临时状态保存本次材料版本、约定起止范围、实际进度、等待何种反馈，以及当前未决问题、已核证据和下一步。论文明确两步阶段；书籍另保留译后等待、入门和细讲阶段，不压成论文流程。

续读时按 session-records.md 读取最新有效索引及相关主记录；用户明确续读时还按主记录检查 `reading-notes.md` 的对应最新书签。先承接未解决问题和待反馈节点；有仍适用的核验证据就复用，不能只凭旧聊天印象重查、跳步或重启导读。未归档的新反馈在当前会话内优先，但不承诺跨聊天恢复未保存内容。保存频率仍依原节点，不增加逐轮持久存储、后台监听或自动备份。

## 已有知识修正的回归检查

例如，已有记录显示用户理解方法和公式的作用，推导尚未掌握。只用已理解的维度衔接新内容，并保留推导缺口。论文的学科分类与存放目录分别核实；单篇记录发生变化时，依证据更新受影响的条目。

已经删除或撤回的来源不因旧索引、画像或备份重新激活。核查 Skill 来源时读过的历史材料不会成为日常教学可搜索的来源。

## 权限 保存与验收状态

使用当前实际开放的文件、检索与视觉工具，不因本文件获得额外执行、浏览器、Skill配置或文件修改权。对原论文、笔记和长期档案的更改仍服从当前授权及原保存规则；原始资料尽量不覆盖。只有实际读到文件、页图、源码或历史记录才据此回答，不承诺完整无损历史、后台记忆或跨会话监控。

日后若要移植 VISTA 程序，可参考 [官方仓库](https://github.com/joshhhhhan/VISTA) 的 `artifacts.py`、`session.py`、`tools.py` 设计，另行具备环境、接口、权限与测试并遵守 MIT 许可；当前未移植，不把规则整合说成自动安装程序。

验收时观察新论文能否先完成工程化导读再等待开始；图式争议能否检查原图并返回当前阶段；是否分别使用方法和公式的掌握记录；续读是否先查可访问的最新档案与书签；持久写入能否重新读取验证。每个小节在第一回合后停下来，用户明确要求细讲后再以通俗短句讲解。

安装是否完成以实际保存的 Skill 配置或可加载文件为准。新会话中的行为单独验证；本地静态校验不能代替交互测试。
